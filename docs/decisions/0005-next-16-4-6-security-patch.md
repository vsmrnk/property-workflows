# 0005. Оновлення Next.js 16.4.3 → 16.4.6: збірка блокується через advisory `use cache`

- Статус: прийнято
- Дата: 2026-11-18
- AC: — (технічне рішення; поведінка AC не змінюється)

## Контекст

`AGENTS.md` фіксує стек «Next.js 16.4» і забороняє оновлювати версії без ADR (попереднє оновлення — ADR 0001).
Застосунок стоїть на `next@16.4.3`. З 2026-11-18 `npm run build` завершується з `SecurityFatalError`, бо для цієї
версії опубліковано два advisory:

- [`GHSA-mfr8-8qww-v76h`](https://github.com/advisories/GHSA-mfr8-8qww-v76h) — medium: розкриття даних між значеннями
  root params, коли функцію `use cache` викликають через `unstable_cache()` (16.3.0–16.4.4);
- [`GHSA-vc7v-qv4w-wrv8`](https://github.com/advisories/GHSA-vc7v-qv4w-wrv8) — medium: витік кешу між значеннями
  root params у вкладених функціях `use cache` (16.2.0–16.4.4).

Наш код `use cache` не використовує (Cache Components вимкнено), тож прямої вразливості в застосунку немає. Але CI
(job `app`) запускає `npm run build`, і доки версія вразлива, він червоний на кожному PR. Перша виправлена версія —
16.4.5; остання патч-версія лінії 16.4 — 16.4.6.

## Рішення

- `next` 16.4.3 → **16.4.6**, `eslint-config-next` 16.4.3 → **16.4.6** (разом, точні версії, як у ADR 0001).
- Інших залежностей не чіпаємо; рядок стеку в `AGENTS.md` («Next.js 16.4») лишається правдивим.
- Окремий PR від `main` без змін коду застосунку; гілки з відкритими PR перебазовуються на `main` після його merge.

## Розглянуті варіанти

- **16.4.5 (перша виправлена)** — ні: 16.4.6 — та сама лінія, останній патч; різниця — лише виправлення помилок, і
  ми не повертатимемось до цього питання через наступний патч.
- **`next upgrade --agent=security` (пропозиція з виводу збірки)** — ні, як і в ADR 0001: інструмент сам обирає, що й
  до якої версії оновлювати; нам досить точкового патчу двох пакетів з контрольованим diff.
- **Вимкнути перевірку безпеки збірки** — ні: це приховує майбутні advisory, а виправлення вже є.

## Наслідки

- `npm run build` знову проходить (`ƒ Proxy (Middleware)`), `next` зникає з `npm audit --omit=dev`.
- Інші знахідки `npm audit --omit=dev` (ланцюжок пакета `shadcn`) з цим рішенням не пов'язані й лишаються як були.
- Ризик регресії малий (патч), його ловить CI: `lint`, `typecheck`, `test`, `build`, `ac:coverage`.

## Як перевіряємо

- Локально: `npm run build`, `npm run lint`, `npm run typecheck`, `npm test` — зелені.
- CI цього PR (`app`: lint, typecheck, test, build) і Preview на Vercel; після деплою — вхід, список ранів, запуск
  шаблону, «Mark as done» на прод-URL.
