# 0001. Оновлення Next.js 16.4.0 → 16.4.3 через критичні вразливості

- Статус: прийнято
- Дата: 2026-10-25
- AC: — (технічне рішення; поведінка всіх AC зрізу 1 не змінюється)

## Контекст

`AGENTS.md` фіксує стек «Next.js 16.4» і забороняє оновлювати версії без ADR. Застосунок стоїть на `next@16.4.0`.
`npm audit --omit=dev` (2026-10-25) позначає `next` 16.0.0–16.4.0 як **critical**, серед іншого:

- неавтентифіковане віддалене виконання коду в Image Optimization API через SVG;
- відмова в обслуговуванні в App Router через Server Actions;
- віддалене виконання коду у функціях `use cache`, що повертають typed arrays.

Наш прод (Vercel) публічний і використовує Server Actions (`launchRun`, `markTaskDone`, `login`), тож друга
вразливість стосується нас прямо. `next build` і `next dev` теж показують попередження й радять оновитись.
Виправлення — у `next@16.4.3`, патч-версії тієї самої лінії 16.4 (не мажорне оновлення).

## Рішення

- `next` 16.4.0 → **16.4.3**, `eslint-config-next` 16.4.0 → **16.4.3** (разом, точні версії, як і раніше).
- Інших залежностей не чіпаємо; рядок стеку в `AGENTS.md` («Next.js 16.4») лишається правдивим.
- Окремий PR, без змін коду застосунку, щоб регресію (якщо буде) було видно ізольовано.

## Розглянуті варіанти

- **Лишити 16.4.0 до кінця курсу** — ні: critical RCE/DoS на публічному проді, а пояснення «шаблон курсу так
  зафіксував» не захищає дані.
- **`next upgrade --agent=security` (пропозиція з оверлею Next.js)** — ні: інструмент сам вирішує, що й до якої
  версії оновлювати, і може зачепити інші пакети; нам досить точкового патчу двох пакетів з контрольованим diff.
- **Оновитись до найновішої мінорної/мажорної версії** — ні: шаблон перевірено лише на 16.4, а `AGENTS.md` прямо
  застерігає від «оновлення всього до latest»; патч у межах 16.4 закриває вразливості з мінімальним ризиком.

## Наслідки

- `npm audit --omit=dev` — 0 вразливостей; попередження в `next build` / `next dev` зникає.
- Ризик регресії малий (патч), його ловить CI: `lint`, `typecheck`, `test`, `build`, `ac:coverage`.
- Якщо шаблон курсу випустить своє оновлення Next.js — переносимо його `git cherry-pick` у PR «Оновлення шаблону»;
  конфлікт буде лише в `package.json` / `package-lock.json`.

## Як перевіряємо

- `npm audit --omit=dev` у PR (вивід — в описі) і CI цього PR (`app`: lint, typecheck, test, build).
- Ручна перевірка після деплою: вхід, список ранів, запуск шаблону, «Mark as done» на прод-URL.
